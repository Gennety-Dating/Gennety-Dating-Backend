# 2026-10-27 — лента основателя уезжает на отдельный бот Gennety

Основатель решил: `@sverkausbot`, через который с 2026-07-16 шла лента
основателя (`FOUNDER_BOT_TOKEN`), становится его рабочим ботом для других
проектов — any и DiskPulse (отдельный репозиторий `~/Developer/work-bot`,
long polling с Mac). Для Gennety создаётся новый, свой бот, и весь функционал
ленты (регистрации, свидания, оплаты, закрытия аккаунтов, недельный отчёт,
рекламные расходы и остальные 11 уведомлений) переезжает туда.

Код не меняется: лента только отправляет сообщения через голый grammY `Api`
и всегда грузит байты фото сама (file_id у ботов разные), поэтому смена бота —
это замена значения `FOUNDER_BOT_TOKEN` в env и перезапуск `gennety-bot`.
`FOUNDER_TELEGRAM_ID` прежний. Ссылки недельного отчёта и страницы расходов
подписаны `ADMIN_API_KEY`, от бота не зависят. Старые сообщения ленты остаются
в чате `@sverkausbot`.

Переходный период безопасен: прод только отправляет через `@sverkausbot`,
рабочий бот читает его обновления (вебхука нет) — конфликта нет, просто
сообщения Gennety и any/DiskPulse идут в один чат до переключения.

Переключение — действие основателя: создать бота в BotFather, нажать в нём
/start, затем `bash ~/gennety-backups/swap-founder-bot.sh` (проверяет токен и
что бот может писать, меняет ключ локально и на проде там, где он задан, с
бэкапом, перезапускает `gennety-bot`). **PENDING:** до запуска скрипта лента
продолжает идти в `@sverkausbot`.

2026-10-28: новый бот — `@gennetyworkspacebot` (создан основателем). Локальный
`.env.local` уже переключён на него; прод — тем же скриптом с флагом `--yes`

## 2026-10-30 — надёжность рабочих ботов

Владелец поручил реализовать улучшения аудита и выбрал сохранить рабочую
часть обоих ботов на Mac. Переноса на новый или существующий сервер нет;
зависимость от сна, питания и интернета Mac сохраняется. Существующий сервер
Gennety используется для шифрованной копии рабочего пространства и внешней
проверки доступности. Новый платный сервис не добавляется.

В Gennety добавлена отдельная файловая очередь транспортных запросов
`sendMessage`, `sendPhoto`, `sendMediaGroup`, `sendDocument` founder-бота:
запись с fsync до отправки, вложения сохраняются вместе с запросом, повтор
после сетевого сбоя и рестарта. Каталог `/var/lib/gennety-founder-outbox`,
права 0700/0600; отправленные записи удаляются. Схема основной БД не меняется.
Доставка at-least-once: Telegram не предоставляет ключ идемпотентности для
неоднозначного сетевого таймаута; редкий дубль возможен. Подготовка уведомления
до транспортного слоя остаётся best-effort; это не транзакционный журнал
всех событий продукта. Demo/dev не включают ленту; существующие ограничения
`FOUNDER_NOTIFY_ENABLED` и runtime suppression остаются прежними.

Новые функции рабочего пространства: создание задачи GitHub из заметки после
подтверждения, её ссылка и статус, переходы в существующие разделы админ-панели.
Операции изменения данных самой платформы Gennety не добавляются.

Предрелизная проверка зависимостей обнаружила GHSA-8g5g-mxqh-grgj для Vite
6.4.4; override обновлён до исправленной 6.4.5. Это dev/build зависимость,
публичный Mini App не требует отдельной публикации для серверной очереди.

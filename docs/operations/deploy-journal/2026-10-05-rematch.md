# 2026-10-05 — Rematch suspended in production and demo

The founder requested temporarily disabling Rematch without removing its code.
A scoped source update was deployed to `/opt/gennety` and `/opt/gennety-demo`;
`REMATCH_FEATURE_ENABLED=false` is effective in both runtimes and in local
backend development. No database migration, dependency installation, Mini App
bundle deployment or native iOS release was needed.

1. Behavior
    - Existing central eligibility guards suppress post-drop, decline and expiry offers and remove the daily banner action on reconciliation.
    - The concierge playbook and tool schema omit Rematch. Old tool calls and offer buttons cannot create a purchase entry.
    - Old invoice links fail pre-checkout. A successful charge arriving after shutdown is durably recorded and refunded, without searching, animating or dispatching a new match.
    - The refund sweep remains registered independently of the sales flag. Existing matches, ordinary matching and purchase history retain their lifecycle.
    - Demo remains disabled and uses the same gate. The native iOS client has no Rematch purchase entry.
2. Verification
    - 201 relevant unit tests passed across eligibility/allocation, refund recovery, payment settlement/pre-checkout, offers, concierge, banner rendering and product playbook. Six new regression tests cover disabled entry points and a late charge.
    - `pnpm --filter @gennety/bot typecheck` and `git diff --check` passed.
    - `pnpm security:secrets` passed. `pnpm security:audit` passed with the same two previously ignored moderate advisories.
    - Before deployment, all six scoped runtime files on both servers matched their local HEAD versions. After deployment, SHA-256 checks matched the updated source.
    - Loading config from each server root reported `REMATCH_RUNTIME=false`. PM2 had no overriding Rematch environment variable; both processes were online with stable restart counts after the intentional restarts. Refund cron registration was present in both startup logs.
    - Production and demo `/v1/ping` both returned `ok: true`. No live payment or user-message test was performed.
3. Recovery and re-enabling
    - Pre-change copies of the six runtime files and environment files are saved at `/opt/gennety-rematch-disable-20261005-001959` and `/opt/gennety-demo-rematch-disable-20261005-001959`.
    - Keep refund recovery enabled when reverting code. Restoring the old cron gate while leaving sales off would stop refund retries.
    - Re-enable only on the founder's instruction: set `REMATCH_FEATURE_ENABLED=true` in the relevant environment file and restart its PM2 process with `--update-env`, then `pm2 save`. Check `.env.local` if present because it takes precedence over `.env`.
    - The earlier settlement/dispatch race findings remain separate follow-up work; this release suspends new purchases and preserves financial recovery.

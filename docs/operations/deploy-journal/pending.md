(2026-09-07).** **Схема Prisma НЕ меняется, новых env НЕТ.** Правки только в

Server Code → `pm2 restart`. Откат — `git revert` и рестарт; ничего не мигрирует,
так что откат безопасен в любой момент.

**Зачем.** Понедельничное напоминание вело на `/ad-spend` дашборда, который
авторизуется Bearer-ключом `ADMIN_API_KEY` из `sessionStorage` — а Telegram
открывает ссылки во встроенном браузере, где этот стор всегда пустой. С телефона
ссылка была тупиком. Теперь напоминание несёт `GET /v1/founder/ad-spend/:token`:
форма без логина, неделя уже подставлена. Плюс исправлены пять багов фаундер-фида
(«amount unknown» на возвратах, `$9.99 EUR`, неделя, зависевшая от часа крона,
500 на дробной сумме, игнорируемый `amountIsEstimate`).

**Предусловие, без которого ссылки в сообщении не будет:** в `/opt/gennety/.env`
должен быть непустой `ADMIN_API_KEY` — из него выводится ключ подписи ссылки.
Он там уже есть (им авторизуется дашборд); проверить, а не предполагать.
**Ротация `ADMIN_API_KEY` гасит все ранее выданные ссылки** — это намеренно, но
знать об этом надо: после ротации старое понедельничное сообщение перестанет
открываться, следующее принесёт свежую ссылку.

**Проверка после рестарта.** Ждать понедельника не нужно — бот на проде
запускается через `tsx` из исходников (не из `dist/`), поэтому напоминание
дёргается тем же интерпретатором:

```bash
cd /opt/gennety && ./apps/bot/node_modules/.bin/tsx -e \
  "import('./apps/bot/src/services/founder-notify.ts').then(m => m.notifyFounderAdSpendReminder())"
```

Затем открыть пришедшую ссылку **с телефона** и убедиться, что форма
открывается без логина, даты подставлены за прошлую Пн–Вс, а сохранение
появляется в `/ad-spend` дашборда КАК РЕДАКТИРОВАНИЕ той же строки, а не как
вторая. И отдельно, что подделанный токен закрыт:

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  https://dating-api.gennety.com/v1/founder/ad-spend/nope   # ожидается 404
```

**Одно поведение стало строже — знать заранее.** `POST /admin/ad-spend` теперь
отвергает канал, который не существует и не похож на `tg:<slug>` / `web:<slug>`
(раньше «Instagram Ads» проходил и создавал канал, на который никогда ничего не
сматчится). Уже залогированные каналы входят в множество разрешённых, поэтому
**ни одна существующая строка не становится нередактируемой** — но если в
`ad_spend` на проде лежит расход со свободнотекстовым каналом, он таким и
останется, пока его не перепишут руками на реальный. Посмотреть, есть ли такие:

```sql
SELECT DISTINCT channel FROM ad_spend
WHERE channel NOT IN ('organic','referral','mobile','unattributed')
  AND channel !~ '^(tg|web):[A-Za-z0-9_.-]+$';
```

**Дашборд (`~/Desktop/gennety-admin-dashboard`) деплоится отдельно** и в этот
блок не входит: там форма теперь подставляет ЗАКРЫВШУЮСЯ неделю (была текущая —
на неделю мимо вопроса, который задаёт напоминание), починен сдвиг даты на день
назад в часовых поясах восточнее UTC и добавлена проверка целой суммы.

**Demo mode:** не затронут — весь фаундер-фид инертен без `FOUNDER_NOTIFY_ENABLED`,
а демо-бот его не включает. **iOS:** не затронут, `/v1/founder/*` не входит в
клиентский контракт.

что `location.html` и `venue-change.html` кэшируются эвристически. Замена

запертом слоте — то есть худшее, что получит закешированный клиент, это 402 без
объяснения, и то лишь после флипа флага. Обратный порядок ломается: новый бандл
попросит инвойс у сервера, который такого маршрута не знает, и получит 404 на
кнопке, которую только что нарисовал.

- **`PREMIUM_FEATURE_ENABLED` — часть гейта, а не соседняя настройка.**

  оставляет только разовую покупку, а это не тот продукт, который описан в §3.8.
  В проде Premium включён, так что после флипа заработает сразу.

- **Пара, уже отметившая слот из полосы, грандфазерится** — проверкой по
  `availableTimesA/B`, а не миграцией. Включение флага не имеет права
  обесценить отметку, сделанную пока он был выключен.
- **Пара, где ОБЕ стороны на приложении, fail-open**: купить пропуск там нечем

- **`purchases.ts` начинает читать пятую таблицу** — `/admin/purchases`,
